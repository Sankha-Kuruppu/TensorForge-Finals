## Why not train a neural network from scratch?

You have only six hours to build the complete product.

Training a multilingual neural network from scratch would require substantially more data and time. Using an existing multilingual embedding model lets us reuse learned language representations and train a relatively small classifier on top.

For the baseline, TF-IDF is even faster and requires no GPU.

# 3. The most important data-design decision: Prevent data leakage

This is where many student ML projects go wrong.

Suppose your dataset contains these two messages:

**Training example:**

> Japan hotel job available. Pay Rs. 50,000 immediately to secure your position.

**Test example:**

> Hotel work in Japan is available. Send Rs. 50,000 now to reserve your job.

If you generate dozens of nearly identical examples and randomly split them, similar templates can end up in both training and test sets.

Your model may achieve impressive scores without learning how to generalize to genuinely new scams.

### The solution

Divide your data into four distinct groups.

| Dataset           | Purpose                        | Example                                          |
| ----------------- | ------------------------------ | ------------------------------------------------ |
| Training set      | Fit the classifier             | Existing job advertisements and scam patterns    |
| Validation set    | Choose the model and threshold | Different advertisements and wording             |
| Held-out test set | Final performance evaluation   | Unseen examples                                  |
| Shifted set       | Demonstrate data drift         | New scam tactics and different language patterns |

A reasonable starting split for the initial labelled dataset is:

* 70% training.
* 15% validation.
* 15% held-out test.

The shifted set should be created separately rather than simply taking another random sample from the same pool.

For synthetic examples, create different templates and scenarios for each split. Where feasible, reserve entire template families or scam tactics for validation and testing.

For a stronger demonstration, reserve a specific new tactic for the shifted set, such as a newly worded fake recruitment campaign.

This makes your drift demonstration much more convincing.

# 4. My recommended model-training strategy

I recommend building the model in two stages.

## Stage A — Train a TF-IDF baseline

Start here because it is fast, easy to explain, and suitable for a six-hour hackathon.

### Why use both word and character features?

Consider the following messages:

* `Pay a processing fee to secure your overseas job.`
* `pay processing fee overseas job`
* `Pay processing fee nowww for Korea job!!!`

Word-level features can capture phrases, while character-level features can help identify spelling variations and unusual word forms.

This can be useful when scam messages use abbreviations, inconsistent spelling, or informal writing.

### Recommended configuration

| Component          | Configuration                            |
| ------------------ | ---------------------------------------- |
| Text features      | Word-level TF-IDF                        |
| Word n-grams       | 1–2                                      |
| Character features | Character TF-IDF                         |
| Character n-grams  | 3–5                                      |
| Classifier         | Logistic Regression                      |
| Class imbalance    | `class_weight="balanced"`                |
| Evaluation         | Precision, recall, F1, average precision |
| Model output       | Saved scikit-learn pipeline              |

A crucial limitation: ordinary word and character TF-IDF features do not provide robust semantic understanding across Sinhala script, Singlish, and English. They are a baseline to compare against, not a guarantee of multilingual performance.

### Baseline training code

This first version trains on EMSCAD so you can establish a reproducible baseline. We will add the Sri Lankan dataset in the next stage.

**Cell 2 — Download and prepare the data**

```python
import pandas as pd
import numpy as np

from huggingface_hub import hf_hub_download

csv_path = hf_hub_download(
    repo_id="victor/real-or-fake-fake-jobposting-prediction",
    filename="fake_job_postings.csv",
    repo_type="dataset"
)

df = pd.read_csv(csv_path)

# Combine the main textual fields.
text_columns = [
    "title",
    "company_profile",
    "description",
    "requirements",
    "benefits"
]

df["text"] = (
    df[text_columns]
    .fillna("")
    .astype(str)
    .agg(" ".join, axis=1)
    .str.strip()
)

df = df[
    (df["text"].str.len() > 0) &
    (df["fraudulent"].isin([0, 1]))
].copy()

df["label"] = df["fraudulent"].astype(int)

print("Total records:", len(df))
print("\nLabel distribution:")
print(df["label"].value_counts())

print("\nExample:")
print(df[["text", "label"]].head(1).to_string(index=False))
```

**Cell 3 — Create training, validation, and test sets**

```python
from sklearn.model_selection import train_test_split

# First, separate the held-out test set.
train_val, test_df = train_test_split(
    df,
    test_size=0.15,
    random_state=42,
    stratify=df["label"]
)

# Split the remaining data into training and validation.
train_df, val_df = train_test_split(
    train_val,
    test_size=0.1765,
    random_state=42,
    stratify=train_val["label"]
)

print("Training:", len(train_df))
print("Validation:", len(val_df))
print("Test:", len(test_df))

print("\nTraining labels:")
print(train_df["label"].value_counts())
```

This produces approximately 70% training, 15% validation, and 15% test data.

For a final, stronger experiment, we should also investigate duplicate or near-duplicate advertisements and use group-aware splitting where necessary.

**Cell 4 — Train the baseline model**

```python
from sklearn.pipeline import FeatureUnion
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

features = FeatureUnion([
    (
        "word",
        TfidfVectorizer(
            analyzer="word",
            ngram_range=(1, 2),
            min_df=2,
            max_features=100_000,
            sublinear_tf=True
        )
    ),
    (
        "char",
        TfidfVectorizer(
            analyzer="char",
            ngram_range=(3, 5),
            min_df=2,
            max_features=100_000,
            sublinear_tf=True
        )
    )
])

baseline_model = Pipeline([
    ("features", features),
    (
        "classifier",
        LogisticRegression(
            class_weight="balanced",
            max_iter=1000,
            random_state=42
        )
    )
])

baseline_model.fit(
    train_df["text"],
    train_df["label"]
)

print("Baseline training completed.")
```

**Cell 5 — Evaluate the baseline**

```python
from sklearn.metrics import (
    classification_report,
    confusion_matrix,
    average_precision_score,
    roc_auc_score
)

X_val = val_df["text"]
y_val = val_df["label"]

val_predictions = baseline_model.predict(X_val)
val_scores = baseline_model.predict_proba(X_val)[:, 1]

print(classification_report(
    y_val,
    val_predictions,
    target_names=["Legitimate", "Fraudulent"],
    digits=4,
    zero_division=0
))

print("Confusion matrix:")
print(confusion_matrix(y_val, val_predictions))

print(
    "Average precision:",
    round(average_precision_score(y_val, val_scores), 4)
)

print(
    "ROC-AUC:",
    round(roc_auc_score(y_val, val_scores), 4)
)
```

### Which metric matters most?

For JobShield LK, pay particular attention to the fraudulent class.

| Metric            | Why it matters                                                                              |
| ----------------- | ------------------------------------------------------------------------------------------- |
| Fraud recall      | How many fraudulent advertisements the model catches                                        |
| Fraud precision   | How many advertisements flagged as fraudulent really are fraudulent in the labelled dataset |
| Fraud F1          | Balance between precision and recall                                                        |
| Average precision | Useful for evaluating the minority fraud class                                              |
| Confusion matrix  | Shows missed scams and legitimate advertisements incorrectly flagged                        |

EMSCAD is heavily imbalanced: only about 4.8% of its advertisements are fraudulent. Consequently, accuracy alone is insufficient. ([Hugging Face][1])

A model that predicts every advertisement as legitimate would achieve high accuracy on this dataset while failing at the main task.

Also, do not choose a final prediction threshold solely to maximize recall. Excessive false alarms could cause users to ignore warnings. Select the threshold on the validation set according to the intended use, then evaluate the chosen threshold once on the held-out test set.

**Important:** The code above is an initial baseline, not your final competition model. It does not yet evaluate Sri Lankan overseas recruitment or demonstrate drift.

# 5. Stage B — Train a multilingual semantic model

After establishing the baseline, we can test your proposed model:

`intfloat/multilingual-e5-small`

Model reference: [multilingual-e5-small on Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small?utm_source=chatgpt.com)

Instead of training a large neural network from scratch, this approach uses the pretrained model to transform text into numerical vectors called **embeddings**.

A classifier then learns to distinguish suspicious and legitimate recruitment content from those vectors.

### Why consider embeddings?

These messages have different wording:

* `Pay a fee to reserve your overseas job.`
* `Send the processing money first to guarantee placement abroad.`

Word-level features can capture some shared vocabulary. Embeddings can also represent broader semantic relationships, potentially helping when the wording changes.

However, this advantage must be measured. It is not guaranteed that embeddings will outperform TF-IDF on your dataset.

### Recommended training procedure

1. Load the pretrained multilingual embedding model.
2. Generate embeddings for the training examples.
3. Train Logistic Regression on those embeddings.
4. Tune model settings and the decision threshold using validation data.
5. Evaluate on the held-out test set.
6. Compare the results with the TF-IDF baseline.
7. Save the winning model and its associated preprocessing configuration.

For a short hackathon, use **frozen embeddings first** rather than fine-tuning the entire transformer. This is faster and avoids unnecessary complexity.

The model can be used for multiple languages, but we must test English, Sinhala, and Singlish independently. Do not assume that performance on English proves performance on the other two.

# 7. Data drift: How to demonstrate that JobShield LK adapts

This is the part that can distinguish your project from a basic text classifier.

Your project should detect changes in scam tactics, not merely classify a few predefined messages.

I recommend creating three separate scenarios.

### Scenario A — Original data

The model learns from examples of conventional overseas-job scams.

Examples involve familiar wording about deposits, visa processing, and job guarantees.

### Scenario B — Shifted data

Introduce examples that use new tactics, such as:

* New destinations.
* Different fee terminology.
* New social-media recruitment styles.
* More Sinhala-English code-switching.
* Alternative ways of claiming that a position is guaranteed.

Do not simply rewrite every existing message by changing a few words. Reserve different scenarios or template families so the shifted data represents a meaningful change.

### Scenario C — Monitoring and response

The system measures changes in incoming data and raises an alert when a configured drift threshold is exceeded.

For example:

| Signal                | What it measures                                     | Possible response               |
| --------------------- | ---------------------------------------------------- | ------------------------------- |
| Input-feature drift   | Changes in text or embedding distributions           | Flag the current data window    |
| Confidence monitoring | Increase in uncertain predictions                    | Route affected cases for review |
| Unknown-pattern rate  | Increase in inputs unlike those seen during training | Raise an unfamiliar-input alert |
| Labelled performance  | Precision and recall on subsequently reviewed cases  | Trigger model reassessment      |

For the first version, I recommend a simple, reproducible drift detector rather than building several complex monitoring algorithms.

You could use a distribution-comparison method such as the Population Stability Index (PSI) for selected numeric features, or a statistical two-sample test for embedding distributions.

A confidence threshold by itself is not a reliable detector of all distribution shifts. A model can be confidently wrong on unfamiliar scams.

**Critical distinction:** Data drift means that incoming data has changed. It does not automatically prove that the model has become less accurate. Use labelled reviewed examples to measure actual performance degradation.

The competition explicitly expects a shifted dataset, a drift signal, and a response such as an alert, safe fallback, human-review route, or retraining trigger.

# 8. Should we train using EMSCAD and synthetic Sri Lankan examples together?

Yes, but carefully.

I recommend the following experiment:

| Experiment | Training data                               | Purpose                                                               |
| ---------- | ------------------------------------------- | --------------------------------------------------------------------- |
| E1         | EMSCAD only                                 | Establish the general English baseline                                |
| E2         | Synthetic Sri Lankan examples only          | Measure how well the classifier learns the locally designed scenarios |
| E3         | EMSCAD + synthetic Sri Lankan examples      | Test whether combining datasets improves performance                  |
| E4         | Best candidate + shifted dataset evaluation | Demonstrate robustness monitoring                                     |

For each experiment, use consistent held-out test data and report results separately for English, Sinhala, and Singlish wherever the sample size supports meaningful evaluation.

Because the datasets have different origins and distributions, do not combine all examples indiscriminately and assume the resulting scores represent real-world performance.

Synthetic examples are useful for development and testing, but a model evaluated exclusively on synthetic data has not established real-world effectiveness.

A strong future validation step would be a manually reviewed collection of appropriately licensed or permissioned recruitment examples, with personal information removed and labels assigned using a documented process.
